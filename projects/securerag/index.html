01 / Architecture

Trust boundaries
before prompts.

The project treats the user, API, retrieval layer, vector store, document content, and hosted model as separate security boundaries.

INPUT

User → FastAPI

The application receives the question and controls which documents are eligible for retrieval.

RETRIEVAL

FastAPI → ChromaDB

Similarity helps find relevant content, but similarity alone is not authorization.

MODEL

Context → Hosted LLM

Retrieved content is potentially untrusted data and should not automatically become instructions.

02 / Security tests

Observed behavior,
not marketing claims.

Two tests have been run so far: indirect prompt injection and RAG poisoning. Their results are intentionally reported differently because the evidence differed.

Not reproduced

Indirect prompt injection

The adversarial document was retrieved, but the tested model did not follow the embedded instruction. Retrieval exposure was confirmed; exploitation was not.

Confirmed

RAG poisoning

A synthetic poisoned document became Source 1 and the model repeated its false claims. This is documented as RAG-001.

Next milestone: defense + retest

The next phase is to enforce trust/authorization in retrieval, rerun the exact same poisoned query, and update the finding with before/after evidence.
