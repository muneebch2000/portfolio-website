02 / security goals

What the lab proves.

  • Retrieval similarity is not authorization.
  • Untrusted documents can influence model behavior.
  • Tenant isolation must be enforced outside the model.
  • Security tests should survive model changes.
  • Findings need remediation and retest evidence.
Attack / defend

Controlled failure modes.
Measurable defenses.

The vulnerable mode is intentionally limited to this lab so the same test cases can be repeated after application-side controls are enabled.

Attack 01

Cross-tenant retrieval

Show how semantic similarity can retrieve another synthetic tenant's document when authorization is omitted.

Attack 02

Indirect prompt injection

Place an instruction inside a controlled test document and observe whether retrieved content changes the model's behavior.

Attack 03

RAG poisoning

Insert misleading lab content, record its provenance, and measure whether it affects retrieval and generation.

Defense

Application enforcement

Filter retrieval by tenant, separate instructions from untrusted context, preserve provenance, add logging, and regression-test the boundary.

03 / evidence package

Portfolio deliverables.

  • Source code and reproducible setup
  • Threat model and trust-boundary notes
  • Synthetic benign and adversarial documents
  • Vulnerable versus defended test cases
  • Security event logging
  • Findings, mitigation, and retest report
04 / scope

Authorized lab only.

All attack scenarios use synthetic data and a controlled application. The project is designed to demonstrate secure AI engineering—not testing third-party systems without permission.

Status: implementation source is published in GitHub. Live hosted-model validation requires a private OpenRouter API key and is performed only in the authorized lab environment.
