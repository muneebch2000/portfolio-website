AI security / deeper coverage

Explore the full lifecycle.

AI security focus areas across the model, application, agent, and infrastructure lifecycle. Practical evidence is developed through the project roadmap.
15 topics
01 / FOUNDATIONS⌁

Foundations & architecture

ML and deep learning, transformers, tokens, embeddings, context windows, fine-tuning, RAG, and agents.

Controls & practice

Map each component, its owner, inputs, outputs, and trust boundary. Separate model behavior from application authorization.

02 / MODELS⌁

Data & training security

Data provenance, consent, sensitive data, poisoning, backdoors, and dataset integrity.

Controls & practice

Track dataset versions and access, review ingestion sources, and test for poisoning or unexpected behavior using isolated evaluation data.

03 / MODELS⌁

Model & supply-chain security

Model provenance, weights, dependencies, serialization, artifacts, and third-party services.

Controls & practice

Verify artifact origin and integrity, avoid untrusted executable formats, pin dependencies, and restrict model loading privileges.

04 / MODELS⌁

Adversarial ML

Evasion, adversarial examples, model extraction, membership inference, and model inversion.

Controls & practice

Define attacker access and realistic objectives. Test model-specific exposure, rate controls, output behavior, and the limits of proposed defenses.

05 / APPLICATIONS⌁

LLM prompt injection

Direct instructions, untrusted documents, tool responses, and persistent malicious context.

Controls & practice

Treat retrieved text and tool output as untrusted data. Enforce permissions outside the model and evaluate layered controls; prompt instructions alone are insufficient.

06 / APPLICATIONS⌁

RAG & vector security

Document access, poisoned retrieval, tenant isolation, embedding exposure, and source integrity.

Controls & practice

Enforce retrieval permissions for each user, preserve source metadata, validate ingestion, and test cross-user access with synthetic records.

07 / APPLICATIONS⌁

Agent & tool security

Excessive agency, unsafe actions, confused-deputy behavior, tool servers, and multi-agent trust.

Controls & practice

Use narrowly scoped credentials, tool allowlists, isolated execution, action validation, approval for consequential actions, and bounded resource budgets.

08 / APPLICATIONS⌁

AI application security

Insecure output handling, authentication, API abuse, secrets, and conventional application flaws.

Controls & practice

Validate and encode model output for its destination. Never directly execute generated commands or queries. Apply standard authorization and secure coding controls.

09 / OPERATIONS⌁

Privacy & data protection

Sensitive prompts, logs, retention, training-data exposure, and provider data handling.

Controls & practice

Minimize data sent to models, redact where appropriate, define retention, isolate access, and test for leakage without using real confidential records.

10 / FOUNDATIONS⌁

Threat modeling & risk

Assets, data flows, trust boundaries, abuse cases, business impact, and attacker capabilities.

Controls & practice

Build a data flow diagram and identify misuse scenarios. Prioritize risks by impact and exposure, then attach a test and an owner to each control.

11 / OPERATIONS⌁

Red teaming & evaluations

Adversarial prompts, misuse scenarios, regression tests, coverage, and reproducible scoring.

Controls & practice

Use authorized test environments, fixed datasets, clear success criteria, and repeatable runs. Track false positives and compare controls against a baseline.

12 / OPERATIONS⌁

Secure MLOps & deployment

CI/CD, model registries, container security, runtime identity, rollback, and release gates.

Controls & practice

Control who can promote models, protect build credentials, record model and data versions, isolate workloads, and verify rollback procedures.

13 / OPERATIONS⌁

Monitoring & incident response

Tool-use traces, anomalous access, leakage signals, drift, and resource abuse.

Controls & practice

Log enough to investigate while minimizing sensitive content. Define alert owners, containment steps, token revocation, and model or pipeline rollback.

14 / OPERATIONS⌁

Governance & assurance

AI inventories, risk ownership, vendor review, policy, documentation, and human oversight.

Controls & practice

Use relevant frameworks to structure review and evidence. Record limitations, intended uses, residual risks, and approval decisions.

15 / OPERATIONS⌁

Resilience & ongoing validation

Denial of service, denial of wallet, failure modes, safe fallbacks, and control decay.

Controls & practice

Set rate and budget limits, test unavailable dependencies, define safe failure behavior, and rerun security evaluations after model or application changes.
